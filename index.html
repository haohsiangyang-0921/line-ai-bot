LINE AI 智慧小助理 (改善版)

整合 Python FastAPI、line-bot-sdk v3 與 Google Gemini 3.8 Flash 的智慧聊天機器人

📌 1. 專題介紹

🎯 想解決的問題

日常生活常有查資料、英文寫作修飾、概念解惑的需求，但經常得反覆切換專用 AI 軟體；傳統聊天機器人遇到非文字訊息時容易「已讀不回」，且本機測試常需開啟多個終端視窗造成使用不便。

👥 目標使用對象

學生、自學者與一般大眾。在熟悉的 LINE 聊天室中，就能隨手獲得 24 小時在線的 AI 智慧助理解答，並讓本機運行更簡潔。

🌟 核心功能清單

  • 自然語言智慧問答：串接 Google 官方最新 gemini-3.8-flash 模型，具備高度語境理解能力。
  • 嚴格簽名安全校驗：使用 HMAC-SHA256 驗證 X-Line-Signature，杜絕惡意偽造請求。
  • 雙模式自動備援機制：未設定 Gemini 金鑰時自動降級至 Echo 模式，保障服務基本可用。
  • 一鍵背景隱形運作：解決原本需常駐開啟兩個終端命令視窗的困擾。

🚀 2. 改善版升級紀錄 (四大核心說明)

依據作業規範記錄：原本的問題 ➔ 修改內容 ➔ 前後差異 ➔ 重新測試結果。
項目 說明與實作內容
1. 原本的問題 • 終端機佔用困擾：原本要在電腦桌面上常駐開啟兩個黑色的命令提示字元視窗（FastAPI 伺服器與 ngrok 穿透），不僅佔用螢幕桌面，還容易被誤關導致機器人下線。
• 非文字無回應：第一版僅處理文字，遇到貼圖或照片時直接忽略無聲（已讀不回）。
2. 修改內容 • 製作一鍵背景運行腳本：撰寫 一鍵隱藏啟動.vbs 與 一鍵關閉停止.bat，讓程式可以在 Windows 背景靜默運行與一鍵終止，免去常駐兩個黑色命令視窗。
• 非文字訊息攔截提示：在 main.py 擴充事件處理，收到貼圖或照片時嘗試回覆友善提示，告知目前僅支援文字對話。
3. 前後差異 • 改善前：桌面常駐兩個黑視窗，使用電腦時容易被干擾或誤關；傳貼圖完全無反應。
• 改善後：點擊腳本即可在背景隱藏執行，桌面乾淨；傳貼圖時能嘗試提供提示導引。
4. 重新測試結果 時好時壞 文字對話功能穩定通過，但背景腳本管理與非文字例外處理偶爾有進程殘留或未觸發情況，如實記錄並列入後續優化。

🛠️ 4. 開發過程紀錄

  1. 階段一：架構計畫與金鑰申請：規劃 FastAPI 與 LINE Messaging API 的互動流程，於 LINE Developers 申請 Provider 與 Channel，取得 Channel Secret 與 Long-lived Token。
  2. 階段二：環境初始化與核心開發：建立 Python 3.12 虛擬環境，導入 line-bot-sdk v3 與 google-genai SDK，撰寫簽名校驗與 Webhook 路由。
  3. 階段三：本地穿透與除錯驗證：配置 ngrok 進行本機端口對映，成功通過 LINE Webhook 簽名驗證，並在手機 LINE 上進行端對端實測。
  4. 階段四：體驗優化與改善版迭代：串接 Gemini 3.8 Flash，並將原本需常駐兩終端機的流程升級為一鍵背景隱藏執行與關閉，完成 GitHub 提交。

💬 代表性指令 (Prompt)

「請規劃一個以 Python FastAPI 與 LINE Bot SDK v3 為核心的 AI LINE 機器人，並串接 Google Gemini 模型進行問答。」

🔍 檢查與修正 AI 產出的真實經驗

在開發過程中，並非全盤盲信 AI，而是親自進行了兩次重要的排錯與校正：

  • 經驗一（Windows 批次檔換行編碼修正）：AI 最初自動生成的 run_ngrok.bat 採用了 Linux LF 換行與特殊字元，導致 Windows 內建的 cmd.exe 執行時發生位元組錯位，跳出 'cho' 不是內部命令 的嚴重錯誤。經過手動除錯檢查，重新撰寫 Python 腳本以純 ASCII 與二進位 CRLF (\r\n) 格式重寫批次檔，徹底解決問題。
  • 經驗二（Gemini 模型名稱過期修正）：AI 原先設定模型為 gemini-2.5-flash，執行時遭 Google 官方回傳 404 NOT_FOUND: This model is no longer available。隨後手動透過 client.models.list() 檢索目前可用清單，確認並修正為最新的 gemini-3.8-flash 模型，順利連線成功。

💡 6. 開發心得與未來限制

🎓 學習心得

• 清楚知道 Webhook 與 ngrok 的通訊與穿透原理。
• 原來要在 LINE 接入 AI 其實相當不容易（牽涉金鑰驗證、網路穿透、SDK 配置等繁瑣流程）。
• 坦白說不敢想像如果沒有 AI 幫助，自己從零摸索會用多久時間。

⚠️ 目前限制與未來展望

• 目前能用到雲端的軟體皆須付費：嘗試部屬至 Render、Zeabur 等雲端時皆遇信用卡或付費買伺服器門檻，無法輕易免費託管。
• 讓一鍵執行與關閉更正常：持續優化背景執行腳本，改善偶爾進程殘留（時好時壞）的現象。
• 遇到不支援的貼圖文字也能更穩定回應：持續強化例外處理與非文字訊息應答能力。
