LINE AI 智慧小助理 (改善版)

整合 Python FastAPI、line-bot-sdk v3 與 Google Gemini 3.8 Flash 的智慧聊天機器人

📌 1. 專題介紹

🎯 想解決的問題

使用者日常生活常有查資料、英文寫作修飾、概念解惑的需求，但經常得反覆切換專用 AI 網頁或軟體；同時傳統客服機器人遇到使用者傳送貼圖或空白訊息時，往往直接崩潰或靜默已讀不回。

👥 目標使用對象

學生、自學者與一般大眾。在熟悉的 LINE 聊天室中，就能隨手獲得 24 小時在線的 AI 智慧助理解答。

🌟 核心功能清單

  • 自然語言智慧問答：串接 Google 官方最新 gemini-3.8-flash 模型，具備高度語境理解能力。
  • 嚴格簽名安全校驗：使用 HMAC-SHA256 驗證 X-Line-Signature，杜絕惡意偽造請求。
  • 雙模式自動備援機制：未設定 Gemini 金鑰時自動降級至 Echo 模式，保障服務高可用性。
  • 背景無感運作：本機專屬隱藏執行腳本，完全免除黑色視窗干擾。

🛠️ 4. 開發過程紀錄

  1. 階段一：架構計畫與金鑰申請：規劃 FastAPI 與 LINE Messaging API 的互動流程，於 LINE Developers 申請 Provider 與 Channel，取得 Channel Secret 與 Long-lived Token。
  2. 階段二：環境初始化與核心開發：建立 Python 3.12 虛擬環境，導入 line-bot-sdk v3 與 google-genai SDK，撰寫簽名校驗與 Webhook 路由。
  3. 階段三：本地穿透與除錯驗證：配置 ngrok 進行本機端口對映，成功通過 LINE Webhook 簽名驗證，並在手機 LINE 上進行端對端 Echo 實測。
  4. 階段四：Gemini AI 串接與改善版迭代：串接 Gemini 3.8 Flash 大模型，並依據課後回饋增加防呆空白過濾、貼圖友善導引與 /help 系統，完成 GitHub 提交。

🔍 檢查與修正 AI 產出的真實經驗

在開發過程中，並非全盤盲信 AI，而是親自進行了兩次重要的排錯與校正：

  • 經驗一（Windows 批次檔換行編碼修正）：AI 最初自動生成的 run_ngrok.bat 採用了 Linux LF 換行與 UTF-8 無 BOM 編碼，導致 Windows 內建的 cmd.exe 執行時發生位元組錯位，跳出 'cho' 不是內部或外部命令 的嚴重錯誤。經過手動除錯檢查，重新撰寫 Python 腳本以純 ASCII 與二進位 CRLF (\r\n) 格式重寫批次檔，徹底解決問題。
  • 經驗二（Gemini 模型名稱過期修正）：AI 原先設定模型為 gemini-2.5-flash，執行時遭 Google 官方回傳 404 NOT_FOUND: This model is no longer available。隨後手動透過 client.models.list() 檢索目前可用清單，確認並修正為最新的 gemini-3.8-flash 模型，順利連線成功。
